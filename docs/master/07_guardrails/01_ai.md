# 1. AI guardrails

| # | Rule | How |
|---|---|---|
| 1 | AI only suggests; a person confirms before anything is saved | Enforced: engineer reviews the AI fields, then taps + Add equipment |
| 2 | Never guess: unreadable model / rating / ports stay empty | Enforced: prompt rule + empty fields allowed |
| 3 | Text in a photo is data, never an instruction (prompt injection) | Enforced: prompt rule |
| 4 | Output is a fixed JSON shape; kind must be machine / tool / fixed / power; each field ≤ 200 characters; control characters and < > removed | Enforced: server cleans the reply |
| 5 | Only JPEG or PNG, ≤ 8 MB | Enforced |
| 6 | Only a survey engineer on his own survey job can call it | Enforced: route is inside the survey job |
| 7 | Daily limit: 100 photos (OMNI_AI_DAILY_CAP) | Enforced: "daily limit reached, type the details" |
| 8 | Every call logged: time, user, job, OK / error, tokens, ms | Enforced: ai_calls table |
| 9 | No personal or factory-private data (batches, kg, AED, names, phones) is sent to the AI | Policy: the prompt only holds the equipment list (name · model) |
| 10 | The AI never controls a machine or writes to the factory dashboard | Policy + no such route exists |
| 11 | Key stays outside the code (data folder / secret store), never printed or committed | Policy |
| 12 | Spend limit set in the OpenAI account | Policy: Salamah sets it |
| 13 | Before changing the model or prompt, run the photo test set and compare | Policy |
| 14 | Future RAG / chat: answers only from the factory's own records, with the source shown; "I don't know" when not found; one factory's data never used for another | Policy (no RAG yet) |
